## Durable write contract

Durable: museum tier/style/grounds/security choice when implemented, registered item rights, display placements, exhibit state, cash and income remainder, tutorial, contracts, lifetime progress, earned cosmetics and existing raid/recovery fields. Temporary: current plot slot assignment, physical clone and socket instance IDs, carrying state, provisional scene objects, preview clones and session navigation targets.

`ProfileService.ApplyOperation` delegates valuable changes to `ProfileRepository.ApplyOperation`. That repository serializes per-user work, validates the candidate schema, records an idempotent operation ID and scope, and reconciles uncertain writes before another valuable operation. `StageRoutine` is for routine staged progress. Task 12 should load and migrate before assigning a writable clone; on load or migration failure, show a loading/error state without a blank writable museum. Plot reservation can remain held temporarily while a pending write is resolved, but it must not be saved as profile ownership.
